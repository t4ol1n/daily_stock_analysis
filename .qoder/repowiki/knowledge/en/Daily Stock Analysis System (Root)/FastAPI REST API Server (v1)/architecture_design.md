The module is organized as a layered FastAPI application. `app.py` defines an `app_lifespan` context manager that bootstrares shared services (`RuntimeSchedulerService`, `SystemConfigService`) on startup and tears them down on shutdown, then `create_app()` wires CORS, the auth middleware, error handlers, health endpoints, and static-file serving for the Vite-built SPA. `api/v1/router.py` is the single aggregation point that mounts each domain endpoint module under `/api/v1/<domain>` with OpenAPI tags. Each domain lives in `api/v1/endpoints/` (e.g. `agent.py`, `analysis.py`, `backtest.py`, `portfolio.py`, `stocks.py`, `system_config.py`, `usage.py`, `alerts.py`, `decision_signals.py`, `screening.py`, `intelligence.py`, `history.py`, `auth.py`, `health.py`) and declares its own `APIRouter`. Request/response contracts are isolated in `api/v1/schemas/` as Pydantic models (one file per domain plus `common.py`). Cross-cutting concerns are factored out: `middlewares/auth.py` implements a `BaseHTTPMiddleware` that enforces session cookies on `/api/v1/*` when `ADMIN_AUTH_ENABLED` is true, and `middlewares/error_handler.py` centralizes exception-to-JSON mapping. Shared dependencies (DB sessions, config, service instances) are exposed via `deps.py` using FastAPI's `Depends` pattern so endpoint functions stay thin. The dependency direction is strictly inward: endpoints → schemas + deps → `src.*` services; the app layer depends only on routers and middlewares.
