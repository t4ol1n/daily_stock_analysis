The module is organized around three layers with clear dependency direction: `models.py` defines the shared data contracts (`BotMessage`, `BotResponse`, `WebhookResponse`, plus `ChatType`/`Platform` enums); `platforms/` provides one adapter per messaging platform implementing the abstract `BotPlatform` in `base.py` (signature verification, message parsing, response formatting, optional stream clients for DingTalk/Feishu); `commands/` provides one command handler per feature (analyze, ask, chat, market, batch, help, status, research, strategies, history) all subclassing `BotCommand` from `commands/base.py`. The top-level `dispatcher.py` hosts `CommandDispatcher`, which owns a registry of commands, a sliding-window `RateLimiter`, admin-user checks, and both sync and async `dispatch()` entry points. It also implements a two-layer natural-language routing path: a regex pre-filter followed by an LLM intent parser (`src.agent.llm_adapter.LLMToolAdapter`) that routes free-form text to `/ask` or `/chat`. `handler.py` is the HTTP boundary: `handle_webhook` / `handle_webhook_async` resolve a platform via the `ALL_PLATFORMS` registry, delegate to the platform's `handle_webhook`, then hand the resulting `BotMessage` to `get_dispatcher()`. A global singleton dispatcher is lazily created by `get_dispatcher()` and auto-registers every class listed in `commands/__init__.py.ALL_COMMANDS`; platforms are similarly cached in `_platform_instances`. Stream integrations (DingTalk, Feishu) are imported lazily and gracefully degrade when their SDKs are absent.
