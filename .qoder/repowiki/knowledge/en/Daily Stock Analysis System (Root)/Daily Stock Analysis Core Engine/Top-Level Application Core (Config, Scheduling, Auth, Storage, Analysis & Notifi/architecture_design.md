This leaf module assembles the application's top-level concerns around a single `src/config.py` `Config` dataclass that is loaded from `.env` via `setup_env()` and consumed by every other subsystem. The runtime loop lives in `src/scheduler.py`, which wraps the `schedule` library with a `GracefulShutdown` signal handler, supports multiple daily times, and dispatches background tasks on a 30-second polling loop; callers register their work through `set_daily_task` / `add_background_task`. Business logic is split into analyzers (`analyzer.py`, `market_analyzer.py`, `stock_analyzer.py`) that call LiteLLM through `src.llm.*` backends and produce structured results, while `notification.py` composes Markdown reports and routes them to many channels via `src.notification_sender` using routing/noise/contract helpers in sibling files. Persistence is centralized in `src/storage.py`, which defines SQLAlchemy ORM models (`StockDaily`, `NewsIntel`, etc.) over a SQLite engine with schema migration tracking (`schema_migrations`). Cross-cutting concerns are isolated: `auth.py` provides file-based PBKDF2 password + HMAC session management behind an `ADMIN_AUTH_ENABLED` toggle; `enums.py`, `formatters.py`, `report_language.py`, `logging_config.py`, `search_service.py`, `feishu_doc.py`, `md2img.py`, `share_image.py`, `phase_decision_guardrail.py`, `daily_market_context_guardrail.py`, `analysis_context_pack_*`, `market_phase_prompt.py`, `market_structure_prompt.py`, `market_phase_summary.py`, `market_context.py` provide shared types, formatting, guardrails, and prompt builders consumed by the analyzers and notifications. Dependency direction is inward toward `config` and outward to `src.agent`, `src.llm`, `src.services`, and external libraries (LiteLLM, schedule, SQLAlchemy); nothing in this scope imports the web UI layer except through optional lazy imports.
