Three-file packaging layer: `Dockerfile` uses a two-stage build — a `node:20-slim` stage (`web-builder`) compiles the Vue/React web app under `apps/dsa-web` into static assets, which are then copied into a `python:3.11-slim-bookworm` runtime image alongside `requirements.txt`, `api/`, `data_provider/`, `bot/`, `src/`, and `strategies/`. System deps include `wkhtmltopdf` (Markdown→PDF/image) and CJK fonts; a post-install smoke test imports `src.services.screening.pipeline` and `futu` to fail fast on missing SDKs. `docker-compose.yml` defines two services sharing an `x-common` anchor — `analyzer` (scheduled mode via default `CMD`) and `server` (FastAPI mode with explicit `--serve-only` command and port mapping). Both mount host directories for `/app/data`, `/app/logs`, `/app/reports`, read-only `/app/strategies`, and a Longbridge OAuth token cache at `/home/dsa/.longbridge`. `entrypoint.sh` runs as root only to repair ownership of writable bind mounts (`/app/data`, `/app/logs`, `/app/reports`, `/home/dsa/.longbridge`), checking SQLite WAL/SHM files when repairing `/app/data`, then drops privileges via `gosu` to the `dsa` user (UID/GID 1000) before executing the container's CMD.
